  - 과일이 바닥 아래에서 솟아오르거나, 플레이어 쪽으로 토스되어 날아옴

  - 머티리얼: `Assets/00. SlashTime/Material/`, 셰이더: `Assets/00. SlashTime/Shader/`
  - 문서: `Docs/`

## 2. 작업 규칙 (사용자 요청 사항)

- **코드 수준:** 취업 연수생 수준으로 단순하게. 사용자가 수업에서 배운 프로젝트(머지 게임, 미니 골프, FPS 게임, XR 던지기 물리)의 스타일을 따른다.
  - 한 줄씩 한국어 주석
  - 조건은 `== false`로 씀 (`!` 대신)
  - 단순한 싱글톤 (`public static X Instance;`)
  - 이벤트는 `SliceSystem`만 씀 (3개). 나머지는 직접 호출
  - FSM, 새 인터페이스나 상속, ScriptableObject 테이블은 쓰지 않음
  - 수학이 들어간 함수는 `// [수학] AI 작성` 표시
- 오브젝트 풀은 이미 있는 FPS 수업의 `IObjectPoolItem` + `ObjectPoolManager`를 그대로 씀
- 바닥 충돌은 LayerMask로 판정 (`LayerMaskExtensions.Contains`)
- **커밋과 푸시는 사용자가 요청할 때만** 한다
- 사용자가 직접 코드를 고치는 경우가 많다. 파일을 고치기 전에 **항상 최신 내용을 다시 읽고**, 사용자가 바꾼 부분은 되돌리지 않는다
- 씬이나 프리팹 YAML은 에디터가 열려 있으면 직접 고치지 않는다. 대신 Inspector에서 할 일을 안내한다
- 코드를 바꾼 뒤 `dotnet build Assembly-CSharp.csproj`로 컴파일을 확인한다 (출력은 임시 폴더로)

## 3. 핵심 설계 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 과일 이동은 Rigidbody + `AddForce` (요청은 Update, 실제 힘은 FixedUpdate) | 포물선 궤적과 바닥 튕김이 자연스러움 |
| **과일 전용 물리 씬** (`FruitWorld`) | `Time.timeScale`은 건드리지 않고 과일만 느리게 하려고. `Simulate(fixedDeltaTime × Scale)`로 직접 진행. 플레이어와 칼은 영향 없음 |
| 칼에는 콜라이더나 Rigidbody 없음. 판정은 과일 물리 씬에서 Raycast 5개(휘두르기) + OverlapCapsule(가만히 대기) | 빠르게 휘둘러도 놓치지 않고, 칼을 가만히 대도 베임 |
| **칼에 닿으면 속도와 상관없이 무조건 베임** | 속도 조건은 연산만 늘고 손맛을 해침 |
| 자르는 면 = 칼날 방향 × 칼이 움직인 방향. 거의 안 움직였거나 찌르듯 움직이면 칼날 면(`transform.right`) | 실제로 그은 방향대로 잘려야 손맛이 있음 |
| EzySlice로 **실시간 메시 절단** (미리 쪼개 둔 모델 안 씀) | 위와 같음 |
| 조각은 다시 벨 수 있음. 한 과일 계열 최대 3번, 최소 반지름 3cm, 쿨타임 0.2초 | 블레이드 타임이 아니어도 여러 번 베기 가능 |
| 과일은 풀링, 조각은 `Instantiate`/`Destroy` (메시도 `Destroy`) | 조각은 자를 때마다 모양이 달라 재사용 불가 |
| 조각과 놓친 과일은 바닥에 닿고 2초 뒤 제거. `killY = -1` 아래로 가면 즉시 제거 | 단순한 안전장치 |
| 블레이드 타임: 게이지 방식. 25% 이상이어야 시작, 가득 찬 게이지로 약 3초, 평상시 첫 절단마다 +10% | 누르는 동안만 슬로우, 게이지는 빨리 닳음 |
| 블레이드 타임 중 베면 **빗금(절단선)만 긋고**, 잘린 조각은 미리 만들어 숨겨 둠. 끝나는 순간 **같은 프레임에 전부 갈라짐** | 한꺼번에 갈라지는 타격감 |
| 빗금 상태로 바닥에 닿으면 그 자리에서 갈라짐 | 단순화 |
| 점수: 첫 절단만 10점 × 콤보 배율(×1, 5콤보 ×1.5, 10콤보 ×2, 20콤보 ×3), 블레이드 타임 중이면 ×2. 모든 절단은 콤보 +1. 놓치거나 2초(과일 시간 기준) 동안 안 베면 콤보 초기화 | 추가 절단은 콤보로만 보상 |
| 역할 분리: 자르기 `SliceSystem`, 점수 `ScoreSystem`, 연출 `SliceFeedback`, 과일 한 개의 상태 `Fruit`, 진행 `GameManager` | 처음에는 Fruit와 GameManager에 기능이 몰려 있었음 (사용자 지적) |
| **절단선은 셰이더 방식**: `TimeSlasher/SlashLine` 셰이더 머티리얼을 과일의 두 번째 머티리얼로 붙이고, 자른 면을 `MaterialPropertyBlock`으로 넘김 | 판 오브젝트를 겹치던 방식은 과일 밖으로 삐져나옴. 셰이더 갤러리의 "디졸브" 가장자리 발광을 변형함 |

## 4. 현재 상태

### 스크립트 (`Assets/10. Scripts/`)

| 파일 | 역할 |
| --- | --- |

| `Blade` | 칼 판정 → `SliceSystem.Cut` 호출, `Vibrate` |
| `SliceSystem` | EzySlice 절단, 블레이드 타임 예약과 일괄 절단. 이벤트 `OnCut`, `OnPiecesReleased`, `OnBatchRelease` |
| `CutInfo` | `OnCut` 이벤트로 넘기는 정보 |
| `ScoreSystem` | 점수, 최고 점수, 콤보 |
| `SliceFeedback` | 과즙, 효과음, 진동, 절단선, 일괄 절단 플래시 |
| `BladeTimeController` | 슬로우 입력, 게이지, `Scale`, 연출(Volume, BGM 피치) |
| `GameUI` | 로비, HUD, 게임 오버 UI, 플래시 |

### 레이어와 충돌 (Project Settings의 Layer Collision Matrix 저장 완료)

- `Ground`(3) 바닥, `Rising`(7) 발사 직후 과일(아무것과도 충돌 안 함), `Fruit`(8) 바닥 위 과일과 조각(Ground와만 충돌)
- Rising에서 Fruit로 바꾸는 시점: 콜라이더 맨 아래 `sphere.bounds.min.y > floorY + 0.02`
- 바닥 `FloorCollider`는 `FruitRoot` 아래에 있는 BoxCollider (윗면 y = 0, 두께 0.5)

### 씬 연결 (`Test.unity`)

- `ScoreSystem` 추가됨. `SliceFeedback.slashLineMat` = `M_SlashOverlay` 연결됨
- `SliceSystem.piecePrefab` = `FruitPiece`
- 오브젝트 풀: `Apple`(부모 = FruitRoot), `Juice`

### 절단선 셰이더

- `Shader/SlashLine.shader`, `Material/M_SlashOverlay.mat` (사용자가 `_Width 0.001`, `_Glow 0.01`, `_GlowStrength 0.1`로 조정함)
- 최대 3개 평면, 과일 기준 좌표로 저장, 더하기 혼합, VR 양쪽 눈 렌더링 매크로 포함
- `SliceSystem`은 조각을 만들 때 `Fruit.BaseMaterials`(절단선 머티리얼 뺀 것)를 넘김 (EzySlice는 머티리얼 수 = 서브메시 수여야 함)
- 예전 `SlashLine.prefab`과 `M_SlashLine.mat`은 더 이상 안 씀 (지워도 됨)

## 5. 해결한 문제 (같은 실수 반복 금지)

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `GameUI.cs:52`에서 NullReferenceException, 플레이 중 HUD 점수가 안 뜸 | 씬에 `ScoreSystem` 컴포넌트가 없었음. 예외 때문에 Update 뒷부분이 실행되지 않음 | 씬에 추가 |
| 사과가 안 보이는데 목숨이 깎임 | Layer Collision Matrix가 전부 체크되어 Rising이 바닥 밑면에 부딪힘 | 매트릭스 수정 (Rising은 없음, Fruit는 Ground만) |
| 올라오는 중에 목숨이 깎임 | 레이어 전환을 피벗(`transform.position`) 기준으로 판단. 콜라이더 Center가 (0, 0.06, 0)이고 생성 시 랜덤 회전이라, 콜라이더가 바닥에 겹친 채 Fruit 레이어가 됨 | `sphere.bounds.min.y` 기준 + 0.02 여유 |
| LayerMask 값을 `gameObject.layer`에 넣음 | 비트값(128)과 레이어 번호(7)를 혼동 | `ToLayerIndex`로 변환 |
| 풀링 과일과 원본 메시가 `Destroy`됨 | `Remove()`가 과일과 조각을 구분하지 않음 | `isPiece`로 분기 |

참고: 사용자는 `Rigidbody.excludeLayers` 방식을 시도했다가 **Rising/Fruit 레이어 전환 방식으로 되돌렸다.** 레이어 전환 방식을 유지할 것.
